# Seguimiento del Proyecto mediante Git y Metodología Scrum

En este documento registré los cambios más importantes de mi proyecto y cómo cada uno se relaciona con las actividades de la metodología **Scrum**. Esto demuestra cómo Git puede usarse no solo para controlar código, sino también como herramienta para organizar y monitorear el progreso del proyecto.

---

## 🟦 Sprint 0 – Planificación y Preparación

### ✔ Commit: "Inicialización del repositorio y estructura base del proyecto"
**Actividad Scrum relacionada:** Preparación del entorno y definición inicial del proyecto.  
**Descripción:** Creé la carpeta principal, inicialicé el repositorio y definí la estructura base del proyecto.

### ✔ Commit: "Creación del Product Backlog inicial"
**Actividad Scrum relacionada:** Elaboración del Product Backlog.  
**Descripción:** Registré las primeras tareas, funciones y requerimientos del proyecto.

---

## 🟩 Sprint 1 – Diseño y Primeras Funcionalidades

### ✔ Commit: "Diseño de la interfaz principal del sistema"
**Actividad Scrum relacionada:** Desarrollo de tareas del Sprint Backlog.  
**Descripción:** Realicé el diseño inicial de la interfaz principal del proyecto.

### ✔ Commit: "Documentación de metodología agregada en rama documentacion"
**Actividad Scrum relacionada:** Comunicación y documentación del sprint.  
**Descripción:** Creé la rama *documentacion* y añadí el archivo con la metodología utilizada.

### ✔ Commit: "Corrección de errores encontrados en pruebas internas"

---

# ✔ Conclusión

Git me ayudó a organizar el trabajo como Scrum organiza el desarrollo.  
Cada commit representó una actividad concreta dentro de un sprint, permitiendo llevar un control claro del progreso, detectar problemas y mantener orden en cada etapa del proyecto.  
El uso de ramas como *documentacion* facilitó separar el desarrollo técnico de la documentación sin causar conflictos.
